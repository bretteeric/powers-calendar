# 執行計劃

## 概述

加載計劃，批判性審查，執行所有任務，完成後報告。

**開始時宣佈：** "我正在使用 executing-plans 技能來實現此計劃。"

**注意：** 告訴你的人類夥伴，Superpowers 在有子代理支持時效果好得多（Claude Code、Codex CLI、Codex App、Copilot CLI 與 Gemini CLI 都算；見 `../using-superpowers/references/` 下的各平臺工具參考）。如果子代理可用，請使用 superpowers:subagent-driven-development 而非此技能。

## 流程

### 步驟 1：加載並審查計劃

1. 確保有一個隔離的工作區：用 superpowers:using-git-worktrees 創建一個，或者核實已有的那個
2. 讀取計劃文件
3. 批判性審查——識別計劃中的任何問題或疑慮
4. 如果有疑慮：在開始之前向你的人類夥伴提出
5. 如果沒有疑慮：創建 TodoWrite 並繼續

**審查時重點檢查：**
- 步驟之間是否有依賴遺漏？（A 依賴 B，但 B 排在 A 之後）
- 驗證條件是否明確？（"確認可用"不算，"運行 `npm test` 全部通過"才算）
- 是否有隱含的環境假設？（Node 版本、數據庫連接、API Key）

**審查示例：**
```
計劃文件：docs/plan.md
任務清單：5 個任務

審查發現：
- 任務 3（添加數據庫遷移）應在任務 2（編寫數據模型）之後，順序正確 ✓
- 任務 4 的驗證條件寫的是"確認功能正常"→ 需澄清：具體跑什麼測試？
- 計劃未提及 Python 版本要求 → 需確認

向夥伴提出：
"計劃整體可執行。有兩個問題：(1) 任務 4 的驗證條件不夠具體，建議改為
'運行 pytest tests/test_api.py 全部通過'；(2) 需要確認 Python 版本要求。"
```

### 步驟 2：執行任務

對於每個任務：

1. **標記為進行中** — 更新 TodoWrite
2. **理解目標** — 重讀任務描述，明確完成標準
3. **執行實現** — 嚴格按照計劃步驟執行（計劃已有小步驟）
4. **運行驗證** — 按要求運行測試或檢查
5. **提交變更** — 每完成一個任務提交一次，commit message 引用任務編號
6. **標記為已完成** — 更新 TodoWrite

**每個任務的節奏：**
```
--- 任務 2/5：添加用戶驗證 ---
[標記進行中]

目標：為 /api/users 添加輸入驗證
完成標準：所有驗證測試通過，無效輸入返回 400

[實現]
- 添加 validateUser() 中間件
- 編寫 3 個驗證規則（email 格式、密碼強度、用戶名長度）

[驗證]
$ npm test -- --grep "validation"
  ✓ 拒絕無效 email (12ms)
  ✓ 拒絕弱密碼 (8ms)
  ✓ 拒絕過長用戶名 (5ms)
  3 passing

[提交]
$ git add src/middleware/validate.js tests/validation.test.js
$ git commit -m "feat: 添加用戶輸入驗證（任務 2/5）"

[標記完成]
--- 任務 2/5 完成 ---
```

**持續自查：**
- 執行過程中持續留意：整體方向還對嗎？有沒有偏離計劃？
- 如果發現前面的實現有問題，先修復再繼續，不要帶著問題往下走

### 步驟 3：完成開發

所有任務完成並驗證後：
- 宣佈："我正在使用 finishing-a-development-branch 技能來完成此工作。"
- **必需子技能：** 使用 superpowers:finishing-a-development-branch
- 按照該技能的指引驗證測試、展示選項、執行選擇

**完成報告模板：**
```
## 執行報告

**計劃：** docs/plan.md
**分支：** feature/user-validation
**任務：** 5/5 已完成

### 完成的任務
1. ✅ 初始化項目結構
2. ✅ 添加用戶驗證
3. ✅ 添加數據庫遷移
4. ✅ 實現 API 端點
5. ✅ 添加集成測試

### 驗證結果
- 單元測試：23/23 通過
- 集成測試：8/8 通過
- lint 檢查：0 個警告

### 偏離計劃的地方
- 任務 3：Redis 配置從 env 改為 config.yaml（經夥伴同意）

### 下一步
按 finishing-a-development-branch 技能處理合併/PR
```

## 何時停下來求助

**在以下情況立即停止執行：**
- 遇到阻塞（缺少依賴、測試失敗、指令不清）
- 計劃有嚴重缺陷導致無法開始
- 你不理解某條指令
- 驗證反覆失敗（同一測試失敗 2 次以上）

**不確定時就問，不要猜測。**

## 常見異常處理

> 🇨🇳 **本節是 superpowers-zh 的增量內容，上游 obra/superpowers 沒有。**
> 它展開的是上一節「遇到阻塞（缺少依賴、測試失敗、指令不清）」的三種具體情形。
> 上游的步驟 1–3 與其餘各節均為逐節翻譯，未被本節改動。


**測試失敗：**
1. 讀錯誤信息，定位失敗原因
2. 區分：是實現 bug？還是測試本身有問題？還是計劃描述有誤？
3. 實現 bug → 修復並重跑
4. 測試有問題 → 修復測試，向夥伴說明
5. 計劃有誤 → 停下來，向夥伴報告並建議修正

**依賴缺失：**
```
任務 3 需要 Redis 連接，但計劃中沒有提及 Redis 配置。
→ 停止執行
→ 向夥伴報告："任務 3 需要 Redis，計劃中未包含配置步驟。
   建議：在任務 3 前插入 '配置 Redis 連接' 步驟。"
```

**指令不清：**
- 不要猜測意圖，不要"合理推斷"
- 列出你的理解和困惑，讓夥伴澄清
- 等待回覆後再繼續

**提交粒度：** 每個任務單獨提交，commit message 引用任務編號。

## 何時回到之前的步驟

**回到審查（步驟 1）當：**
- 夥伴根據你的反饋更新了計劃
- 根本性的方案需要重新考慮

**不要硬闖阻塞** — 停下來問。

## 注意事項
- 先批判性審查計劃
- 嚴格按照計劃步驟執行
- 不要跳過驗證
- 計劃要求時引用相應技能
- 遇到阻塞時停下來，不要猜測
- 未經用戶明確同意，絕不在 main/master 分支上開始實現
