# 定向複審提示詞模板

在一輪修復之後分派複審時使用此模板。複審者核實那些發現是否已被解決，
並檢查修復 diff 有沒有引入新的破壞。這**不是**一次全新審查——完整審查
早已做過了。

**目的：** 核實上一次審查的每一條發現都已解決，且修復本身沒有破壞任何東西。

```
Subagent (general-purpose):
  description: "複審任務 N 第 R 輪修復"
  model: [模型 —— 必填：按 SKILL.md 的"模型選擇"來選；省略模型會默默
         繼承會話裡最貴的那個]
  prompt: |
    你正在複審一個任務的一輪修復。之前的審查產生了一批發現，
    一個實現者已經嘗試修復它們。你的工作是給每條發現下結論、
    並檢查這次修復的 diff——僅此而已。

    ## 任務

    讀取任務簡報：[BRIEF_FILE]

    ## 待核實的發現

    [FINDINGS]

    ## 修復

    讀取實現者的報告（修復報告追加在文件末尾）：
    [REPORT_FILE]

    **修復基線：** [FIX_BASE_SHA]（上一次審查所看到的那個 head）
    **Head：** [HEAD_SHA]
    **diff 文件：** [DIFF_FILE]

    把 diff 文件一次讀完——它包含修復的提交、stat 摘要，以及帶上下文的
    修復 diff。不要重新跑 git 命令。如果 diff 文件不存在，自己取 diff：
    `git diff --stat [FIX_BASE_SHA]..[HEAD_SHA]` 和
    `git diff [FIX_BASE_SHA]..[HEAD_SHA]`。

    你的審查對這個 checkout 是隻讀的。不要以任何方式改動工作樹、索引、
    HEAD 或分支狀態。

    ## 範圍

    你的範圍就是那份發現清單和這次修復的 diff。**每一條發現都要給結論。**
    檢查修復 diff 裡有沒有修復本身引入的新問題。**不要**去複審這次修復
    沒有碰過的代碼：如果你注意到一個完全在修復 diff 之外的問題，
    把它寫進"範圍外的觀察"——它不阻塞本任務，也不會延長修復循環。
    覆蓋整個分支的寬範圍審查會在所有任務完成後另行進行。

    ## 測試

    實現者已經重跑了覆蓋被改動代碼的那些測試，並把結果追加到了報告文件裡。
    把報告當作**未經核實的聲明**來對待：確認修復報告點名了覆蓋用的測試
    並給出了它們的輸出，再拿這些聲明去對照 diff 核驗。不要為了確認它的報告
    而重跑整個測試套件。只有當讀代碼引出了某個現有運行結果無法回答的
    具體疑問時才跑測試——而且只跑一個聚焦的測試，絕不跑整包套件。

    ## 輸出格式

    你的最終消息就是報告本身：直接從第一條發現的結論開始。每一行都應該是
    一個結論、一條帶 file:line 的發現，或者一項你實際做過的檢查——
    不要開場白，不要過程旁白。

    ### 各條發現的結論

    按"待核實的發現"裡的順序，逐條給出：
    - **[發現的一句話概括]** —— ADDRESSED（已解決）| NOT ADDRESSED（未解決），
      附 file:line 證據。"嘗試過了"不算已解決：那個具體缺陷必須已經不存在。

    ### 修復 diff 裡的新破壞

    修復本身破壞或引入的任何東西，附嚴重度（Critical/Important/Minor）
    和 file:line。乾淨就寫"無"。

    ### 範圍外的觀察

    你注意到的、完全位於修復 diff 之外的問題。不阻塞；控制者會把這些
    記進賬本留給最終審查。沒有就寫"無"。

    ### 結論

    **本輪修復：** [所有發現均已解決，無新的 Critical/Important 破壞 |
    仍有發現未解決] —— 把未解決的那些列出來。
```

**佔位符：**
- `[MODEL]` —— 必填：審查者模型，按 SKILL.md 的"模型選擇"來選；小修復 diff
  的定向複審用便宜到中檔的層級即可
- `[BRIEF_FILE]` —— 任務簡報文件（與實現者所依據的是同一個文件）
- `[FINDINGS]` —— 上一次審查裡的 Critical/Important 發現和規格差距，
  逐字抄下來，每條一個 bullet
- `[REPORT_FILE]` —— 實現者的報告文件（修復報告追加在其末尾）
- `[FIX_BASE_SHA]` —— 上一次審查所看到的那個 head
- `[HEAD_SHA]` —— 當前提交
- `[DIFF_FILE]` —— `scripts/review-package PLAN_FILE FIX_BASE HEAD` 打印出的那個路徑

**複審者返回：** 逐條發現的結論（ADDRESSED / NOT ADDRESSED）、
修復 diff 裡的新破壞、範圍外的觀察，以及一個本輪結論。
